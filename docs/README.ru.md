# PokéDesk

[English README](../README.md) · [Устройство проекта](architecture.md) · [Подготовка установки](SOURCE_SETUP.md)

Локальное приложение для Pokémon третьего поколения: отдельное игровое окно,
панель команды, справочник, автотренировка, поиск покемонов и Python-скрипты,
которые управляют текущей игровой сессией. **F9 возвращает управление игроку.**

**Сейчас опубликованы исходники, а не готовая игровая сборка.** Репозиторий не
содержит полного установщика зависимостей и ресурсов. Одного клонирования и
добавления ROM недостаточно для запуска игры. Рабочая частная установка рассчитана
на macOS с Apple Silicon. Основной путь проверки — FireRed; для LeafGreen, Ruby и
Sapphire тоже есть адаптеры, но покрытие маршрутов и сюжетных событий ограничено.

## Скачать и проверить исходники

1. Установи Python **3.12 или 3.13** с [python.org](https://www.python.org/downloads/macos/).
2. Для Git установи инструменты Apple командой `xcode-select --install`, либо
   скачай исходники через **Code → Download ZIP** на странице репозитория.
3. В папке исходников выполни:

```sh
git clone https://github.com/redmoongames/pokedesk.git
cd pokedesk
python3 -B tools/public_checks.py
```

Публичные проверки не требуют игры, сохранений или нативного ядра. Они проверяют
контракты кода и безопасный экспорт. CI дополнительно собирает wheel и sdist на
Linux и macOS; это не означает проверку полноценной игры на этих платформах.

Для установки исходников в виртуальное окружение:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -e .
.venv/bin/pokedesk --help
```

## Что нужно для игры

Пока нужна отдельно подготовленная совместимая установка PokéDesk. Публичного
скачивания полного пакета ресурсов и runtime сейчас нет. Его компоненты:

- собственный ROM поддерживаемой редакции;
- совместимое ядро [mGBA](https://github.com/mgba-emu/mgba) и нативный адаптер PokéDesk;
- вложенный Python/Tk для Mac с чипом M;
- символы нужной версии игры, справочники и данные навигации;
- при необходимости — локальные спрайты.

Источники и ограничения компонентов описаны в [SOURCE_SETUP.md](SOURCE_SETUP.md)
и [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md). Обычная установка mGBA или
RetroArch не заменяет эти зависимости. Скрипт `native/build.py` собирает адаптер
с уже подготовленным ядром, но не собирает весь проект с нуля.

В подготовленной установке используй её обычный launcher. Команда, установленная
из исходников, может явно выбрать готовую установку:

```sh
.venv/bin/pokedesk --root PATH_TO_PRIVATE_INSTALLATION
```

Основная поддерживаемая версия FireRed — английская USA/Europe **revision 1**,
16 МиБ, SHA-1 `dd5945db9b930750cb39d00c84da8571feebf417`, локальный файл
`Data/FireRed.gba`. Поддерживаемые редакции перечислены в
[editions.py](../src/pokemon_red/editions.py). ROM нужно получить самостоятельно;
в репозитории нет картриджей, ссылок на ROM и инструкций по их скачиванию.

## Основные действия

- **Команда:** HP, XP, типы, состояния и карточки покемонов.
- **Тренировка:** выбери покемона и целевой уровень; проверь маршрут, команду,
  решения по приёмам и эволюции, затем запусти тренировку.
- **Поиск:** открой автоловлю со страницы вида; укажи пол, shiny, приоритеты
  характеристик, время поиска и при необходимости точные IV.
- **Управление:** F9 забирает управление у бота; клавиши и скорость настраиваются
  в Settings. Python-скрипты выполняются с правами пользователя, это не песочница.
- **Сохранения:** отдельные прохождения, слоты, автосохранение и история откатов.

Скриншоты настоящего интерфейса находятся в [основном README](../README.md).
Они сняты в отдельной демосессии и показывают настройку, а не результаты замеров.

## Сохранения и обновления

Храни резервную копию всей переносимой установки, включая `Data`, `Profiles` и
`Sessions`. Задания закрепляют код, Python, ядро и справочники за своей версией;
обновления включаются после обычного перезапуска. Старые версии сохраняются для
активных и возобновляемых заданий; автоматической очистки кэша пока нет.

Рабочие сохранения, ROM, журналы, спрайты, извлечённые данные игры и бинарные
зависимости не публикуются. Не прикладывай рабочую папку установки к issue.
В публичном коде для изображений предусмотрено только явное исключение для
проверенных скриншотов документации.
